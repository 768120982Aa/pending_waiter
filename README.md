# pending_waiter — 话没说完？我等你

识别"我想想""我看看"等未完信号，回复简短确认并等待续文，合并后统一处理。让 Bot 不再在你话说到一半的时候抢答。

## 工作原理

```
用户: "我觉得这个方案……嗯，我想想……"
  → 插件拦截 → LLM 确认是"话没说完" → 回复"嗯，你说。"
  → 进入等待模式

用户: "算了还是换个思路吧"
  → 收到续文 → 合并调用 LLM → 统一回复
```

## 安装

把 `pending_waiter/` 整个目录放到 `AstrBot/data/plugins/` 下，重启 AstrBot 即可。把 pending_waiter.zip 文件通过webui界面加载也可以。

## 配置

插件目录下的 `config.json` 可自定义所有行为参数。修改后重载插件即可生效。

### 主要配置项

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `timeout` | `60` | 等待续文的超时时间（秒） |
| `skip_prefixes` | `["/", "#", "!", "。"]` | 跳过这些开头的消息 |
| `keywords` | 见配置文件 | 关键词正则列表，命中后走 LLM 判断 |
| `acknowledgments` | 见配置文件 | 简短确认回复，按关键字匹配 |
| `judge_prompt` | 见配置文件 | 发送给 LLM 的判断 prompt，`{text}` 会被替换为用户消息 |
| `judge_system_prompt` | `"你是一个判断助手。只回答是或否。"` | 判断 prompt 的系统提示词 |
| `merge_template` | `"{original}\n——接着：{continuation}"` | 合并原文和续文的格式 |
| `timeout_message` | `"嗯？还在吗？没回话我先忙别的了。"` | 超时提示 |
| `empty_message` | `"嗯？你说。"` | 收到空消息时的提示 |
| `fallback_message` | `"嗯，你接着说。"` | LLM 调用失败时的兜底 |

### 针对人格 / Agent 调校

不同人格的确认语气可以完全不同。比如你的人格是个暴躁老哥：

```json
{
  "acknowledgments": {
    "想": "想好了没？",
    "看": "你倒是看啊。",
    "等": "不等了，快点。",
    "_default": "有屁快放。"
  }
}
```

或者你想纯用正则、关掉 LLM 判断，把 `judge_prompt` 改成一个必定返回"是"的 prompt 就行。
（不过这样就失去了防误判的能力。）

### JSON 中的 `_说明` 字段

`config.json` 中所有以 `_` 开头的字段（如 `_说明`、`_说明_`）仅供阅读参考，插件不会加载它们。

## 行为边界

- **日常对话**：关键词预检不命中则零开销，完全透明
- **指令消息**：以 `/` `#` `!` `。` 开头的消息自动跳过
- **误判防护**：命中关键词后需 LLM 二次确认才进入等待，减少误触发
- **超时兜底**：等待 60 秒无人回复后自动清除，不阻塞后续对话
- **群聊**：不区分消息是否面向 bot，命中即触发。建议结合 @提及过滤自行扩充

## 资源消耗

- 95% 的消息只经过 7 条正则匹配（<1ms）
- 仅命中关键词时消耗一次极小 LLM 调用（~30 token，只回"是/否"）
- 等待状态下每个用户占用一个 SessionController 对象

## 日志

插件关键节点会输出 `pending_waiter:` 前缀的日志：

```
pending_waiter: 进入等待 —— [我想想……]
pending_waiter: 收到续文 —— [我想想……\n——接着：算了换个思路吧...]
pending_waiter: 判断失败 —— ...
```

## 兼容性

- 使用 AstrBot 官方 session_waiter 机制，与其他插件的会话控制不冲突
- 等待期间不影响其他用户的消息处理
- 最低要求：AstrBot >= v4.5.7
